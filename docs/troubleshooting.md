# 出问题时看这里

按现象查。前四类是"能不能跑起来"，后四类是"跑起来但不好使"。

## 一、点登录没反应 / 浏览器没打开

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 弹「打不开浏览器」 | 系统里没有默认浏览器 | 手动访问弹窗里的链接，登录完回到 App 就行 |
| 浏览器打开了但页面白屏 | 网络或登录服务异常 | 换个网络重试；确认 `www.workbuddy.cn` 能正常访问 |
| 登录页显示成功，App 一直「等待授权」 | 轮询没拿到令牌 | 等满 5 分钟会超时，重点一次登录（state 一次一换，不能复用旧链接） |
| 重试多次都在「申请登录会话」失败 | 端点变了或网络被拦 | 拔掉代理/VPN 再试；代理会拦下 `X-No-*` 这类自定义头 |

登录是**轮询式**的：App 申请一个 `state`，浏览器登录后服务端把令牌挂在这个 `state` 上，
App 每秒问一次。所以不需要浏览器跳回 App，也不需要回调 scheme。

## 二、报「账号令牌被拒绝」

App 会自动用 refreshToken 换一次新令牌再重试。如果还不行：

1. 退出登录（会删掉本机密文）→ 重新登录。
2. 换机、恢复出厂、清了应用数据之后，Keystore 里的密钥会没，旧密文解不开——
   代码里会把坏数据删掉并要求重新登录，这是预期行为。

## 三、报 `HTTP 4xx / 5xx`

| 码 | 含义 | 处理 |
| --- | --- | --- |
| 401 / 403 | 令牌失效且刷新失败 | 重新登录 |
| 404 | 端点路径变了 | 说明服务端改过接口，得更新 `Config.REQUEST_PATH` |
| 429 | 触发限流 | 等几分钟；别在循环里狂试 |
| 5xx | 服务端异常 | 稍后重试；同一句话连续失败三次就别试了 |

## 四、无障碍开关打不开 / 是灰的

- **Android 13+**：侧载应用默认被「受限设置」挡住。
  App 里点「应用信息」→ 右上角 ⋮ → **允许受限设置** → 回去再打开无障碍。
- **小米 / 红米**：设置里还有一层「无障碍 → 已下载的应用」，部分机型要求登录小米账号。
- **华为 / 荣耀**：在「应用启动管理」里把本 App 设为手动管理，否则服务会被杀。
- **OPPO / vivo**：电池 → 后台耗电管理 → 允许后台活动。

### vivo（OriginOS）完整清单 —— 把开关被关掉的概率降到最低

无障碍开关被系统关掉，几乎都发生在应用被**强停**之后（从最近任务划掉、一键清理、
i 管家加速都可能触发）。强停这件事没有任何应用能阻止——包括 dsh-Go。
真正的解法不是"防止被关"，而是"被关之后自己写回来"，见下一节。

先把这几件事做完，减少被强停的次数：

1. **最近任务里锁定**：多任务界面 → 下拉 WB 手机助手的卡片 → 点 🔒 锁定。锁定的应用不被一键清理。
2. **i 管家 → 应用管理 → WB 手机助手 → 启动管理**：允许「关联启动」「自启动」「后台高耗电」。
3. **应用信息 → 权限 → 后台弹出界面**：允许。这是任务结束后自动把对话页拉回前台的前提，
   没有它就只会收到一条「任务完成」通知。
4. 电池 → 后台高耗电 → 允许。

### 让它自己把开关写回来（一次性授权，推荐）

应用里的开关状态，说到底是 `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 这个字符串。
拿到 `WRITE_SECURE_SETTINGS` 权限的应用，可以像系统设置页那样把它写回去。
dsh-Go 的「不会掉」就是这个：它 manifest 里声明了这条权限，掉了两秒内自己写回，
再用「摘掉 → 等一秒 → 加回」的方式把「无法运行」也踢醒。**它同样会被杀，只是你看不见。**

授权一次，永久有效（升级不丢，卸载重装才需要重来）：

1. 手机：设置 → 关于手机 → 连点版本号打开开发者选项 → 打开 **USB 调试**
2. 电脑装好 adb（platform-tools），数据线连上手机，手机弹窗点「允许调试」
3. 电脑命令行执行：

```
adb shell pm grant cn.wbphone.agent android.permission.WRITE_SECURE_SETTINGS
```

4. 回到 App → 右上角「⋯」→ 设置 → 应显示 **自动恢复无障碍：已授权**

授权之后的行为：

- 开关被关掉（设置里显示「已关闭」）→ 2 秒内写回，通知栏那条自动变回「无障碍已连接」。
- 开关还在但显示「无法运行」→ 十秒内做一次摘除/重加，逼系统重新绑定。
- 重启手机、应用升级后 → 开机广播和包替换广播会各补一次。
- 连续失败会退避（5 秒、10 秒、20 秒…最多 10 分钟一次），不会和系统死循环。

**不想让它自作主张**：设置里把「自动恢复无障碍」关掉，或者退出登录。
关掉之后你手动关无障碍，它就不会再写回来了。

开关打开后，App 里那行红字会变绿「无障碍服务已开启」。

## 五、模型说「无障碍服务未开启」，但明明是开的

- 服务被系统回收了：回到 App 看一眼那行提示还是不是绿的；必要时关掉开关再打开一次。
- 部分厂商在锁屏后会冻结无障碍服务，解锁后自动恢复。任务跑到一半锁屏就会中断。

## 六、点不动 / 点错地方

- 报 `STALE_SCREEN`：这是正常保护。任何动作之后旧序号都会作废，模型必须重新读屏。
  如果它反复报这个，说明它在偷懒复用序号——把这句话丢给它："每次动作后先 read_screen"。
- 报 `NO_SUCH_INDEX`：序号越界，当前屏元素没那么多。通常也是没重新读屏。
- 报 `NOT_CLICKABLE`：那个元素确实不可点（纯文本标签），该点它旁边的容器。
- 点了但界面没变：多半是悬浮窗或输入法遮挡。让它先 `phone_press_key back` 收起键盘。
- 完全没反应且报 `GESTURE_REJECTED`：屏幕锁着。解锁后再跑。

## 七、读屏读不到字

自绘界面（微信、支付宝、部分小程序 WebView）在无障碍树里是空的，这是 Android 的固有边界。

1. 让模型调 `phone_screenshot`，它会直接看到画面（模型自己会判断该截图）。
2. 看过之后就能点了：模型用 `phone_tap_at` 报图上的像素坐标，手机按缩放比换算成真实坐标。
   一次操作 = 「截图 → 点」两步；点完旧图就作废，要继续操作得重新截。
3. 想手动确认画面：App 里有「截一张屏幕看看」按钮。

### 截图相关的三种失败

| 现象 | 原因与处理 |
| --- | --- |
| 报 `UNSUPPORTED` | 系统低于 Android 11，`takeScreenshot` 不可用。只能读屏，拿不到画面 |
| 报 `SCREENSHOT_TIMEOUT` | 8 秒没回调。通常是系统卡了，或截图被安全策略拦截（部分金融 App 会拒绝截图） |
| 报 `SCREENSHOT_FAILED` 带错误码 | 系统侧拒绝，常见于 DRM 保护页面。这类页面本来也不该被自动化 |

### 坐标点按的两种失败

| 现象 | 原因与处理 |
| --- | --- |
| 报 `STALE_SCREEN`（提到"还没有可用的截图"） | `phone_tap_at` 之前必须 `phone_screenshot`。没有坐标系就没法换算 |
| 报 `OUT_OF_BOUNDS` | 坐标是按真实屏幕尺寸给的。模型该按**图片**的像素尺寸给（图被缩到 1080 宽了） |

点歪了不要连着试——重截一张，让模型对着新图重新定位，比反复猜省 token。

模型把截图当成万能钥匙、每步都截的时候，积分会明显变快——日志里 `token 输入 N` 会直接显示出来。

## 八、跑一半卡住 / 一直循环

- `Config.MAX_TURNS`（默认 12）会兜底，到上限会明确说"没跑完"，不会无限转。
- 卡住时点「停止」。停止会同时叫醒等待中的审批，不用等它超时。
- 反复点同一个序号是模型判断失误，不是程序 bug。清空上下文重说一遍通常就好。
- 如果它连着被审批闸门拦了三次，会自己停下来——这是设计，不是故障。

## 八点五、弹出「需要你确认」/ 一直被拒绝

**这个框是故意的，不是 bug。** 模型要执行付款、输入密码、输验证码、删除这类动作时，
手机在执行前会拦下来等你点头——提示词管不住的事只能靠代码管。

| 现象 | 说明 |
| --- | --- |
| 只在 App 里弹框 | 正常情况下。切到别的 App 时会改成发通知 |
| 只收到通知没看到框 | 点通知回到 App，框会自动补上 |
| 直接报 `USER_DENIED` | 你点了「拒绝」，或者点了「停止」。模型会停下来说明情况，不会重试 |
| 报 `APPROVAL_TIMEOUT` | 120 秒没回应，按拒绝处理。想放宽就改 `ApprovalPolicy.timeoutSeconds` |
| 明明不危险也被拦 | 词表误伤。在 `RiskRules` 顶部的 `PAYMENT_WORDS` / `DESTRUCTIVE_WORDS` 里删掉那个词 |
| 真的危险却没被拦 | 词表漏了。把那个按钮的文字加进对应词表即可，规则是纯字符串匹配，改完就跑 |

三个按钮的区别：
- **允许这次**：只这一次。同一个按钮下次还问。
- **本任务允许**：本任务内，**这一处**不再问。换个位置（比如从「付款方式」换到「确认支付」）仍会问。
- **拒绝**：动作不会执行，模型收到一条说明并停下。

想让闸门少打扰：点「本任务允许」比反复点「允许这次」省事，但它只对同一个目标生效——
这是刻意的，避免"允许了无害的入口"顺带把"真正的付款键"也免检了。

## 九、积分消耗比预期快

- 一屏大纲约 50–100 tokens，工具数据本身很小；大头永远是对话轮次与上下文长度。
- **一张 1080 宽截图约 961 tokens，是读屏的 15 倍。** 如果日志里 `token 输入` 涨得离谱，
  多半是模型频繁截图。可以直接交代一句"尽量别截图，用读屏"。
- 旧图会被自动降级成一行占位文本，所以历史里不会越堆越多——但最新那张每轮都会重发。
- 长任务会不断把历史带上，第 10 轮时上下文已经很厚了。**用「清空」开新话题**是最有效的省法。
- 只想问问题不想动手机时，直接把无障碍关掉也行——模型会收到明确错误，不会瞎点。

## 九点五、语音输入点了没反应 / 提示「没有语音识别服务」

先看 **设置 → 语音 → 语音输入** 那一行，副标题会直接说出缺哪一环：

| 显示 | 意思 | 怎么办 |
| --- | --- | --- |
| 缺麦克风权限 | 清单里有 RECORD_AUDIO，运行时还没批 | 点那一行，系统弹框里选允许；之前拒绝过就去 设置 → 应用 → 月溯 → 权限 → 麦克风 手动开 |
| 没有识别服务 | 设备上没有系统级「语音转文字」服务（vivo 等部分国产 ROM 常见） | 点 🎤 会弹说明框，点「打开键盘」，用输入法自带的话筒说——识别跟着输入法走，字一样进输入框 |
| 可用 | 权限和识别服务都齐了 | 回对话页点输入框旁的 🎤 说，说完点 ■ |

两条容易搞错的事实：

- **RECORD_AUDIO 是调用方要的权限。** 录音虽然发生在识别服务进程里，但 `SpeechRecognizer`
  校验的是**调用 App** 的权限，清单里没有或运行时没批，任何设备都直接返回
  `ERROR_INSUFFICIENT_PERMISSIONS`——这条删过一次，语音就全废了，别再删。
- **App 不做离线识别**：ASR 模型动辄几百 MB，中文效果还不如输入法；云端转写走网关塞音频块
  被 11101 拒过（报文解析层就不认音频）。

## 十、真机上已经确认的

| 项 | 结果 |
| --- | --- |
| 安装 APK | 通过 |
| 登录（浏览器跳转 → 轮询拿令牌 → 回 App 变绿） | 通过 |
| 无障碍服务开启，模型能读屏、点按 | 通过 |
| 端到端任务执行 | 通过 |

还没被长时间验证的，是这几件（不是 bug，是没跑到那个场景）：

- **挂着跑 30 分钟以上**会不会被 ROM 的省电策略杀掉。
- **锁屏/息屏后**无障碍是否被冻结。
- **截图在金融类 App 上**是否被安全策略拒绝（`SCREENSHOT_FAILED`）。
- **自绘界面的点按**：能看见，但序号可能不存在，表现为"模型看懂了却点不下去"。
