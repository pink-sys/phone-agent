# 月溯 · 手机操作 Agent

一个跑在 Android 手机里的 AI agent：读得懂屏幕、点得动按钮、能往输入框里写字、
能自己判断下一步做什么。模型在云端，**引擎在手机上**——不需要电脑配合，不需要局域网，
电脑关着也能用。

- 零第三方依赖：没有 AppCompat、没有 OkHttp、没有 Retrofit、没有 Gson。
  网络用 `HttpURLConnection`，SSE 手写解析，界面全部代码构建。
- 只用系统给的两样能力：**无障碍服务**（手和眼）与**截图 API**（API 30+）。
- 全部动作经过一道**审批闸门**：付款、密码、验证码、删除这类操作在执行前拦下，用户点头才放行。
- **烧的是你自己的 WorkBuddy 积分**：登录谁的账号就扣谁的积分，没有公共 Key 可蹭；
  默认模型 Hy4 flash 当前倍率 `x0.00`（限时免费，11/16–11/30），换到别的档位就按倍率扣。细节见[登录](#登录)、[积分](#积分花的是你自己的)。

```
┌─────────────────────────── 手机 ────────────────────────────┐
│  MainActivity / ChatUi（登录 · 对话 · 日志 · 审批 · 工作台）  │
│        │                                                     │
│  AgentHost   会话、线程、落盘、流水账                          │
│        │                                                     │
│  AgentLoop   模型 → 工具 → 结果回填 → 再问模型，直到收敛      │
│    ├── CloudClient   POST /v2/chat/completions，读 SSE 流     │
│    ├── Auth          轮询式登录 + Keystore 加密存令牌         │
│    ├── PhoneToolbox  23 个工具 ──→ Approval 拦截敏感动作      │
│    │                    └──────→ 无障碍服务（读屏/点按/输入）  │
│    └── Workbench     文件、文档、网页、记忆、技能、shell       │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTPS
                        云端推理接口
```

## 下载安装

到 [Releases](https://github.com/pink-sys/phone-agent/releases) 下载 `yueshu-1.0.0.apk`
传到手机上安装，打开后**先登录**（见下节），再按 App 内的引导开启三项权限：
**无障碍服务**（手和眼）、**悬浮窗**（任务跑到别的应用上时显示状态胶囊）、**通知**（审批提醒）。

- 最低 Android 8.0（`minSdk 26`）；截图相关能力要 Android 11 及以上，低版本会自动降级成读屏大纲。
- APK 用仓库里的本地 keystore 签名。自己构建时首次会生成**一台机器一份**的证书，
  所以自建包和 Release 包不能互相覆盖安装，切换时要先卸载；同一来源的后续版本直接覆盖安装，数据保留。
- 每个 Release 都附 SHA-256，下载后可以自己核对：

  ```bash
  sha256sum yueshu-1.0.0.apk     # Windows: certutil -hashfile yueshu-1.0.0.apk SHA256
  ```

## 登录

**必须登录才能对话**——模型在云端，用的是你自己的账号，没有本地模型可退。第一屏就是登录：
点「打开浏览器登录」→ 系统浏览器打开授权页 → 用你的 WorkBuddy 账号确认 → 切回 App，
它自己就进去了（页面上有「正在等你确认」的转圈，5 分钟内确认完都算数）。

为什么要绕一趟浏览器：

```
App     POST /v2/plugin/auth/state?platform=…        → { state, authUrl }
浏览器   打开 authUrl，你在那边确认授权
App     GET  /v2/plugin/auth/token?state=…  每 1 秒问一次，拿到 accessToken 就停
```

这条链不校验客户端指纹，所以**手机可以独立登录，不需要电脑在旁边陪着**。
授权页长什么样（账号密码 / 扫码 / 验证码 / 二次验证）由服务端决定，App 不参与，
也**不经手你的密码**——它只认最后那个 `accessToken`。

- **令牌存在哪**：Keystore 里的 AES-256/GCM 密钥加密后写私有 SharedPreferences。
  密钥在 TEE/StrongBox 里导不出来，`shared_prefs` 被拷走也解不开。
  过期前用 `refreshToken` 自动续；续不动就退回登录页，不弹错误弹窗打断你。
- **换手机 / 恢复出厂 / 清应用数据**：Keystore 里的密钥跟着没了，密文解不开，
  重新登录一次即可——令牌不会跟着账号同步，这是刻意的。
- **退出登录**：设置 → 退出登录，删本机令牌并清掉当前对话上下文。
- **端点在哪**：`Config.kt` 的 `BASE_URL` / `REQUEST_PATH` / `MODEL` 三个常量。
  要指向自建网关就改这里（协议是 OpenAI 风格的 `/v2/chat/completions` + SSE 流）。

登录跑不通时看 [`docs/troubleshooting.md`](docs/troubleshooting.md) 的头两节
（「点登录没反应 / 浏览器没打开」「报账号令牌被拒绝」）。最常见的三种：手机没设默认浏览器、
代理或 VPN 把 `X-No-*` 这类自定义头拦掉了、浏览器里确认完超过 5 分钟没回来——
第三种重点一次登录就行，`state` 一次一换，旧链接不能复用。

## 工具

模型能用的工具分两组。**手机工具**负责「看和点」，**工作台工具**负责「读和写」——
后者关在沙箱目录里，不弹审批。

### 手机（11 个）

| 工具 | 做什么 |
| --- | --- |
| `phone_status` | 设备型号、屏幕尺寸、无障碍是否可用 |
| `phone_read_screen` | 遍历无障碍树，压成带序号的紧凑大纲 |
| `phone_intent` | 系统意图一步到位：闹钟/计时器/日程/拨号盘/短信草稿/分享/导航/开链接/设置页。**不走无障碍、不占屏幕租约** |
| `phone_tap` | 按序号点：序号 → bounds 中心 → `ACTION_CLICK`，失败退手势 |
| `phone_tap_at` | 按**截图坐标**点：换算成真实屏幕坐标后走同一条路径 |
| `phone_long_press` | 按截图坐标长按约 1 秒（唤出粘贴菜单这类场景） |
| `phone_input` | 输入文字；读不到控件树的应用只写剪贴板（见下文「三步粘贴」） |
| `phone_press_key` | 返回 / Home / 回车等系统键 |
| `phone_launch_app` | 中文应用名 → 包名 → 启动 |
| `phone_swipe` | 直线滑动（滚动列表、拖动滑块） |
| `phone_screenshot` | 截图给模型看；支持只截一块并放大 |

### 子代理（1 个）

| 工具 | 做什么 |
| --- | --- |
| `task` | 派一个只读子代理去查资料/通读一批页面或文件，只把结论带回来 |

- **它解决的是上下文污染，不是智力问题。** 一次 `web_search` 能抓回三千字，这些字如果
  进了主线，之后**每一轮**请求都要跟着重发一遍——而它们对最终决策几乎全是噪声。
  子代理把这些噪声关在自己的历史里，跑完即丢，主线只付一份结论的钱。
- **能力是白名单**：子代理只有 `fs_read` `fs_list` `fs_search` `web_fetch` `web_search`，
  碰不到屏幕、写不了文件（`execute` 里还会再挡一次，不只靠 schema）。
- **看不到主对话**：所以 `goal` 必须写成能独立看懂的一句话；结论里必须自带地址、文件名、
  行号这类证据——它写「见上文」主线是看不到的。
- **跟着停**：用户点停止，子代理立刻收手（不然屏幕上停了、钱还在另一个循环里花）。
- **额度 3 次/任务**：每个子代理都是真金白银的若干轮请求，用完就让它用现有工具自己做。
- token 也记账：子代理烧的算进本轮用量，界面上的数字才和账单对得上。

### 工作台（14 个）

`fs_list` `fs_read` `fs_write` `fs_edit` `fs_search` `web_search` `web_fetch`
`pdf_write` `pptx_write` `docx_write` `html_preview` `memory_save` `skill_load` `shell`（默认关闭）

- **HTML 渲染**：写完网页调 `html_preview`，App 内置 WebView 全屏渲染
  （localStorage、相对路径的 css/js/图片都可用）。页面经本机回环 HTTP 服务
  （`ArtifactServer`，只绑 127.0.0.1）加载，产物卡的「↗」对网页文件也是直接
  拉起系统浏览器打开同一个地址——**不走红 #content:// 分享**，实测手机浏览器
  拿到 content:// 会把它整段当搜索词发给搜索引擎，根本打不开。

- 联网搜索：`web_search` 直接给标题/链接/摘要，`web_fetch` 抓具体页面。没有搜索时，
  模型遇到「某大赛主题四是什么」只能拿训练记忆凑编号——实测凑错了还整段答得很自信。
  引擎顺序 **百度 → 百度移动版 → 必应 → DuckDuckGo**，实测结论：
  - 必应对国内长尾内容基本只给噪声（查「三创赛」回「中国征兵网」「三（汉语汉字）」），
    DDG 国内不可达（350 字节跳转页），所以两个百度排前面；
  - 移动版是独立链路：桌面版偶发回 1KB「安全验证」页时，移动版通常还通；
  - **搜索页按 3MB 读，不是正文抓取的 512KB**：百度一页 895KB、第一个 `<h3>` 在 687KB 处，
    按 512KB 截断会一条都抽不到、静默退到必应拿噪声——这是「搜索一直未命中」的真因；
  - 结果里带 `fallbacks`，写明前面每个引擎为什么没出结果（HTTP 302 / 反爬验证页 / 0 条），
    排查不用再靠猜；只能靠必应时额外给 `warning`，叫模型别顺着噪声编；
  - 提示词同时约束「换关键词最多三次」，防止无限空转烧 token。
- `httpGet` 自己跟重定向（最多 5 跳，含 http→https 跨协议）：JVM 的自动跳转不跟跨协议，
  会把 302 原样当结果返回（3chuang.net 就因此一直报「HTTP 302」）。
- 路径沙箱：所有读写只能在应用私有工作目录里，`../` 与外部绝对路径直接拒。
- 编辑带唯一性校验：要改的那段文本在文件里出现多次就报 `AMBIGUOUS`，不猜。
- 文档零依赖手写：`.docx` 是手写 OOXML（A4、1.5 倍行距、首行缩进、真项目符号），
  不是拼 HTML 改后缀。
- 技能包：`skills/` 下的 Markdown 技能，系统提示里只注入索引，正文由模型按需 `skill_load`。
  内置 9 个：周报、笔记、简历、幻灯片、消息代写，加上从 Anthropic 官方 skills 改写来的
  文档排版、幻灯片章法、长文档协作、写技能。播种带版本号——升级只补新增的，删掉的不会复活。
- 记忆/技能看得见也管得着：设置页「长期记忆」进管理页（最新在上、逐条删、手动记、全清），
  「技能包」点一行看正文、右侧才是开关。记忆一旦参与决策，就得有个地方能查它凭什么这么说。
- 思考可回看：每轮思考全文跟着那条回答一起存进会话（`_think`，单条 4000 字上限），
  退出重进仍能展开；发请求前剥掉——那是模型自己想过的，再喂一遍白烧 token，
  严格的网关还会因为不认识的字段直接 400。
- 过程收拢：跑的时候工具调用、旁白、思考都实时可见；整轮结束收成**一行**
  「✓ 已完成 · N 次工具调用 · M 段说明 · K 次思考」，点开还能逐个看 chip、展开思考全文。
  历史对话打开就是收好的形态——要的是结果，过程留在手边不挡路。
- 人情味开关（设置 → 通用，**默认关**）：开了之后回答先接住情绪再干活，说话像聊天；
  语气段走末条消息的尾部注入，不动 system 正文（前缀缓存不掉），关掉一字不烧。
- 闪退留尸检：未捕获异常写进 `files/crash.log`，下次启动弹一行异常名——
  手机上常年不接数据线，这一行就是唯一能定位的线索。

## 关键设计

### 1. 定位：序号优先，坐标兜底

**序号**省 token 也不怕算错：模型读一次屏拿到 `[2] 关于手机`，点的时候只说 `index: 2`，
坐标由手机从 bounds 算中心点。

**坐标**是给自绘界面准备的——微信、支付宝、游戏在无障碍树里几乎是空的，读屏拿不到序号，
但截图看得一清二楚。这时模型报**截图上的像素坐标**，手机按 `真实屏宽 / 图宽` 换算。

坐标准确性做了三件事，都是被真机打回来才加的：

- **截图自带坐标网格**：发模型之前画上浅橙网格（120px 一格、240px 一个刻度数字，数字就是
  图片坐标）。模型从「凭感觉估」变成「读刻度、数格子」，误差从上百像素压到十几像素。
  数字画在图里，图片中途被缩放也不失效。
- **局部放大截图**：`phone_screenshot(x,y,w,h)` 只截一块（比如长按后弹出的「粘贴」菜单），
  放大到 1080 宽再看。小字看不清导致的点错直接消除。
- **输入框吸附**：落点差几十像素、正好落在输入框边缘外面时，自动吸附到 56px 内最近的输入框
  中心——只吸附输入框，不吸附按钮（误触按钮的代价太高）。

两条纪律：没截图不准坐标点按（`STALE_SCREEN`）；点完旧图作废，要继续点必须重新截图。

### 2. 自绘界面（微信）：三步粘贴

微信整棵控件树对无障碍**完全不可读**（连官方 uiautomator 都返回空节点），
`ACTION_SET_TEXT` 返回成功但字根本不进。所以微信这类应用走一条固定流程，三个工具各管一件事：

```
phone_input(文字)          → 只写系统剪贴板（同一段文字 120 秒内不重复写）
phone_long_press(x, y)     → 在截图量出的输入框位置长按 900ms，唤出菜单
phone_tap_at(x, y)         → 重新截图，点菜单里的「粘贴」
```

为什么不合成一个工具：合成之后模型看不见中间状态，菜单没出来它会以为整步失败然后重试，
一路烧到轮数上限。拆开之后每步都能对着截图确认，哪步失败重做哪步。

还有两个真机踩出来的细节：

- **长按 900ms**：系统长按阈值 500ms，700ms 在部分 ROM 上仍被判成点击。
- **自家悬浮胶囊会截手势**：状态胶囊挂在 `TYPE_APPLICATION_OVERLAY`，手势是屏幕级注入，
  谁在最顶层就落在谁身上——点搜索框变成点胶囊，松手就跳回对话页。修法是派手势期间
  在调用线程上同步置「手势中」标记，胶囊的触摸监听看到就直接吞掉事件（窗口标志
  `FLAG_NOT_TOUCHABLE` 要等下一帧才生效，会被竞态击穿）。

### 3. 审批闸门

提示词里写「付款前要问用户」是靠不住的：模型会忘、会被屏幕文字带偏。
所以闸门在**执行层**——动作发出之前按三条依据判风险：

1. 屏幕事实（包名、可见文本、焦点是否在密码框）
2. 动作参数（要输的文字、要点的目标文本）
3. 规则词表（付款、转账、删除、验证码、密码……）

判成敏感就悬浮卡拦下，用户点确认才放行。拒绝返回 `USER_DENIED`，只放一次就再问，
连续被拒 3 次直接中止任务。密码和验证码在日志里只有 `••••（N 字符，已隐藏）`。

### 4. 上下文压缩：摘要不套娃，原文另有流水账

历史每轮整条重发。一次读屏一百来 token、一张截图九百、一次文件读动辄上千——
十几轮之后光重发历史就能把上下文撑满，模型还会在噪声里丢重点。
`AgentLoop.maybeCompact` 在历史超过 4.8 万字符时把前半段折成摘要，保留最近 8 条（约 4 轮往返）。

压缩有三个不显眼但致命的地方，都是被真机教育出来的：

- **切点不能劈开 `tool` 和它的 `assistant(tool_calls)`**，劈开服务端直接拒掉整个请求。
  所以切点只要求「非 tool 消息」，不限定 user——手机任务通常只有一条 user 指令，
  限定 user 等于永远压不动。
- **摘要不能套娃**。摘要是条 user 消息，早期实现第二次压缩时把它当新目标又包一层，
  变成「目标：[早期步骤摘要…目标：[早期步骤摘要…]]」，任务越埋越深，模型最后连自己要干什么
  都不知道。现在摘要带 `compact` 标记，压缩时**解包继承**最初的目标，过程行并入新摘要；
  旧版本留下的套娃摘要也能被剥到最内层的原始任务。
- **压缩了要告诉用户**：日志里打一行，界面上画一条灰色注记行，不让人疑惑「它怎么忘了」。

**查历史靠流水账，不靠模型上下文。** `Transcript` 给每个会话追加一个
`transcripts/<会话id>.jsonl`：每句用户原话、每次工具调用（参数、成败、结果摘要）、
每段回答、每次压缩、每次报错，发生即落盘，只追加不压缩。模型上下文怎么瘦身都动不到它。

这份记录曾经是「只写不读」——数据一直在攒，入口一个都没有，注释里写的「工作台能拿来看」
其实也拿不到（它在 App 私有目录）。现在有两处入口：会话列表长按 →「看流水账」，
或设置页 →「这个会话的流水账」。里面有耗时拆解（预填 / 想 / 出字各占多少）、
每次调用的参数与返回、压缩和重试。**能整份复制，也能导出成工作台里的 Markdown**——
答错了、点错了，先看这里，比靠回忆和截图猜快得多。

### 5. 提示词与采样

同一个模型，在不同客户端上表现能差一截，原因通常不在模型：

- **提示词**（`PhonePrompt.kt`）把流程、读屏解读、失败手册写死：先读屏判断结构，
  再决定点序号还是按坐标；哪一步报错就照错误提示重做那一步，不换路线。
- **动作后强制核对**：动作类工具成功后会附 `screen_after`（新屏幕大纲），
  模型在同一轮里就能确认是否生效，不用再单独读一次屏。微信的写入/长按是盲操作，
  不附这个——附了只会让模型去「确认字进没进去」然后卡住。
- **采样参数显式给**（`Config`）：`temperature=0.2 / top_p=0.9 / max_tokens=8192`。
  操作类任务每一步都有唯一正确答案，高温只带来随机跑偏。
- **思考深度可选**（设置 → AI → 思考深度）：低 / 标准 / 高，映射到请求体的
  `reasoning_effort`。**默认标准 = 不带这个参数**，请求体和旧版逐字节一致。
  被明确拒绝时会自动摘掉它重发一次并把服务端原话记进日志/流水账（不会每轮都试）。

  实测（当年在 hy3 上做的，同一道难题各 3~5 次，经本地网关直连上游；hy3 已下线，换模型后结论未必成立）：

  | 档位 | 思考 tokens（中位） | 整轮耗时（中位） |
  |---|---|---|
  | 低 | 1,221 | 35.8s |
  | 标准 | 4,592 | 93.6s |
  | 高 | 3,716 | 82.2s |

  低档真的省：思考量约为标准的 1/4，整轮快一半以上。**高档和标准没有可分辨的差别**，
  界面上也不再暗示它能「想得更细」。注意这是难题上的差别；问「你好啊」这种，
  三档都只思考约 200 tokens，看不出区别——判断档位效果必须用会让人想很久的题。

### 6. 请求前缀稳定 + 连接复用

速度与积分的大头都在「每轮都重付一次」的地方，两处都做了消除：

- **系统提示字节级稳定**：长期记忆与技能索引**不**拼进 system（那是每轮都可能变的），
  而是附在最后一条 user 消息上，带「不是本轮指令」分隔头。内容不变时，
  被附的消息逐字节不动，服务端的上下文缓存可以从消息 0 一路命中到尾部；
  真变了也只作废从那条消息起的一段。模型看到的注意力位置几乎没变——那条消息本来就贴着对话的当前端。
- **连接复用**：SSE 流读完只关流、不 `disconnect`——`disconnect` 会连底层 socket 一起关，
  JVM 的 keep-alive 池永远空着，每轮都重付一次 TCP+TLS 握手。只有报错/取消（流没读完）才断开。

### 7. 算一下「慢」到底慢在哪

实测（同一台手机、同一个模型，几十轮样本）首字延迟几乎是一条直线：

```
首字 ≈ 1.35s + 0.0191 × 思考 token     R² = 0.990
```

也就是说，**每 100 个思考 token 约 1.9 秒**。对照着看，9,345 token 的固定前缀
命中缓存与全部失效之间只差 0.27 秒——**砍提示词换来的速度几乎是零，代价却是稳定性**。
所以真正值得动的旋钮只有一个：让模型少想。

这条结论不该靠「我感觉快了/慢了」来判断，`tools/analyze_speed.py` 把流水账按档位分组算：

```bash
python tools/analyze_speed.py          # 连着手机，自动 adb 拉流水账
python tools/analyze_speed.py --dir X  # 分析已经拉下来的 jsonl
```

它输出每档的首字/整轮/思考字数中位数，并直接给出判词：思考字数没降 = 上游没认这个参数；
首字差不到 0.15 秒 = 落在噪声里；样本少于 8 轮 = 现在下结论等于掷硬币。

### 8. 网络自愈：一次抖动不该让整轮白跑

这个 App 跑在手机上，而手机网络本来就是会断的——切 Wi-Fi、进电梯、隧道里没信号。
所以「请求发出去了但没回来」不是异常路径，是**日常路径**。原来四种情况全都直接失败：

| 情况 | 原来的表现 | 现在 |
| --- | --- | --- |
| 429 限流 / 5xx | 弹红字「HTTP 429」，整轮白跑 | 按 `Retry-After` 或 0.7s / 2s 退避重发，最多 2 次 |
| 建连就失败 | 同上 | 同上（这时一个字节都没发，重发零副作用） |
| 吐了半截、连接被掐 | 半截答案留在屏幕上，看着像答完了 | 撤掉半截（`onRestart` 清屏）→ 重发 → 界面上只留完整那份 |
| `finish_reason=length` | 停在半句话上，界面上像正常结束 | 往历史里补一句「接着写」，最多续 2 次 |
| 最终还是失败 | 历史里留一条没人回答的 user 消息 | 撤掉它——否则用户重发一次，等于同一句话问了两遍 |

两条判断依据要说清楚：

- **`finish_reason` 必须读**。它是「模型没说完但没报错」的唯一显式信号；`length` 和正常 `stop`
  在流里长得一模一样，不看这个字段就只能瞎猜。
- **「没有结束标记」不等于「一定被截断」**。`[DONE]` 和 `finish_reason` 两样都没有时只记
  `unmarked`，只有**内容为空**才当断流重发；内容非空时照常返回并记日志。
  一刀切成断流的话，碰上不给标记的网关，每一轮都会重试三遍再报错——那才是真的坏。

重试期间界面会显示「触发限流，2.0 秒后重试」这类话。不显示的话，用户看到的是一段
没有任何动静的空白，然后手动点停止——那才是真的白跑。流水账里也记一条 `retry`，
事后分得清「等网络」和「等模型」。

### 9. 手机独占：同一块屏幕，同一时刻只给一个会话

会话是可以并行跑的（同时开两个对话，各跑各的），但**手机只有一块屏幕**。
两个任务交错操作时坏得很难看，而且每一步单独看都合法、事后翻历史看不出问题：

- 序号表是 `PhoneToolbox` 上的字段。B 一开始跑就 `beginTask()` 清表，A 手里那串
  「第 3 项」当场失效，接着 A 按旧序号点下去，就点到了别的地方；
- 截图坐标系同理：A 的点按是按 A 那张图换算的，B 一截图 `lastShot` 就换了，坐标全错；
- 手势往同一块屏幕 dispatch，两边各点各的，最后落在哪个界面说不清。

`PhoneLease` 把「操作手机」做成全局独占资源：**第一次碰屏幕时申请，一直持有到任务结束**
（不是一次工具调用一申请——读屏算序号、再按序号点，这两步必须在同一个所有权窗口里）。
拿不到就明确拒绝，`AgentLoop` 收到这个拒绝立刻收手，把原因说清楚：

> 另一个会话正在操作手机，这个我先停在这里（没做任何操作）。

不这样做的话，模型会换一个手机工具接着试，一轮里连撞四五次，每次都是同一条拒绝——
白烧 token，界面上还是一片一模一样的话。

只挡碰屏幕的工具。纯聊天、写工作台文件、搜索不需要租约，所以「并行」依然成立，
只是不能同时操作手机。租约在任务收尾（成功 / 出错 / 被停）一定交还，
否则一次异常就让手机被永久占住，用户只会一直看到「另一个会话在操作手机」。

## 构建

### 方式 A：不装 Android SDK（推荐）

只需要 JDK 17 和几个 Maven 构件（`aapt2 / kotlinc / d8 / apksigner`），
脚本自动完成 `aapt2 → kotlinc → d8 → 签名 → 验签`：

```bash
python tools/build_apk.py              # 日常构建 → build/app-debug.apk
python tools/build_apk.py --release    # 发版构建 → build/yueshu-<版本>.apk
```

两者共用同一套工具链和同一份 keystore。`--release` 额外做两件事：

1. **不编入任何凭证**——`Secrets.kt` 按空值生成，APK 里的字符串能被原样抠出来，
   编进去就等于公开；发布包的语音听写因此是关闭的，用的人填自己的 `secrets.properties` 重构建即可。
2. 产物命名为 `build/yueshu-<版本>.apk`，并在末尾打印 SHA-256，直接贴进 Release 说明。

版本号写在 `tools/build_apk.py` 顶部的 `VERSION_CODE / VERSION_NAME`，与 `app/build.gradle.kts` 保持一致。

工具链位置用 `WB_ANDROID_TOOLS` 指定，清单见 [`tools/README.md`](tools/README.md)。
工程路径含中文时脚本会自动复制到 ASCII 临时目录再编译（`aapt2` 按系统代码页解析参数）。

**凭证不进仓库。** 语音听写用的讯飞凭据写在仓库根目录的 `secrets.properties`（已 gitignore）：

```properties
IAT_APP_ID=...
IAT_API_KEY=...
IAT_API_SECRET=...
```

构建时自动生成 `Secrets.kt`。没有这个文件也能构建——语音听写自动关闭，其余功能不受影响。

### 方式 B：Android Studio

直接打开本目录（`minSdk 26 / targetSdk 34`）。仓库里没有 `gradle-wrapper.jar`，
首次同步选 Studio 自带的 Gradle，或先跑一次 `gradle wrapper`。

  没有话题词时退回纯新鲜度（老行为不变）、话题词真的传到了记忆源
- 网络自愈：429 退避后成功、吐了半截被掐断则撤掉重发（界面不出现「半截+完整」）、
  `finish_reason=length` 自动续写、一直 503 时重试有上限且给一句人话、
- 记忆管理页：单条删除只认整行（不误伤同类更长的那条）、删不存在的返回 false、
  删完文件头还在、能接着再记；技能行点开是正文、右侧才是开关
- 思考落盘：每轮思考都进了历史、重启后装回去还能跑、**任何一次请求的 messages 里都没有 `_think`**、
  剥掉字段后工具调用与结果仍配对完整、失败后不留没人回答的 user 消息
- 手机独占：租约只能被持有者交还（别人撬不掉）、B 开始任务不清 A 的序号表、
  撞上别人占着手机时**一轮内收手**（不空转、不抢锁）、交还后别的会话能接手
- 流水账渲染：用户原话、耗时拆解（预填/想/出字）、工具参数与成败、压缩与重试都在，
  跨天分节，渲染后不再残留原始 JSON
- 异常翻译：429 / 5xx / 401 / 超时 / DNS 各自翻成「该等、该换网、该重登」，
  中文说明原样透传，没见过的英文留一句原文
- 子代理隔离：**子代理抓回来的页面不进主线历史**（主线只看到一次 `task`）、
  只读白名单拒写、进度会报到界面（不卡在「派子代理…」）、token 算进本轮用量、
  跑到轮数上限时报「没完成」而不是把半截过程当结论

`tools/README.md` 记录了这套无 SDK 工具链的来历（`dl.google.com` 连不上，
于是直接用 Maven 上发布的构建构件拼了一条流水线）。

## 已知限制

1. **坐标点按很贵**：一次「截图 → 点」是 961 tokens 加一次模型调用。能用序号就用序号。
2. **坐标准不准取决于模型看图**：1080 宽的图上通常够用（容错 ±20px），小图标密集的界面会偏，
   偏了就重新截图，别拿同一张图连点几个位置试。
3. **审批闸门是字符串匹配，有漏**：把付款拆成几步不含敏感词的动作就能溜过去。
   它防的是明显的那几条，不是万能护栏。词表在 `Approval.kt`，误判/漏判直接加词。
4. **无障碍开关只能人工打开**，没有任何代码能绕过。应用能做的是：前台服务降低被回收概率、
   被关掉 2 秒内自动写回（需要 `WRITE_SECURE_SETTINGS`，adb 授权一次）、断了立刻提示。
5. **厂商省电策略**会杀后台（小米/华为/OPPO/vivo），需要允许后台活动；
   「任务结束自动回到对话页」还需要「后台弹出界面」权限。
6. **截图需要 Android 11+**（`takeScreenshot` 是 API 30 起），低版本只能读屏。
7. **依赖非公开接口**：登录与推理端点没有文档、没有版本承诺，服务端改字段就得跟着改。
8. **两个会话不能同时操作手机**：先碰屏幕的那个持有手机到任务结束，另一个会停下并说明原因。
   想同时干两件事，让它们一个操作手机、一个查资料/写文件。
9. **这是个人自用项目**：跑起来烧的是你自己的 WorkBuddy 积分，用多少扣多少，没有「无限量」这回事。

## 安全

- 令牌用 Android Keystore 里的 AES-256/GCM 密钥加密后存私有 SharedPreferences，
  密钥在 TEE 里导不出来；退出登录直接删密文。
- 登录全程不碰密码：授权页在系统浏览器里打开，账号密码直接提交给服务端，
  App 只轮询拿一个 `accessToken`，也不注入任何 JS 到那个页面。
- 截图只在你（或模型）明确调用截图工具时发生，不是每步都传。屏幕上如果有验证码、
  银行余额这类内容，说一句「不要截图」，模型会退回读屏。
- 被闸门拦下的密码/验证码不进任何日志。
- 仓库里没有任何真实凭据：语音听写的 Key 在本地 `secrets.properties`（已 gitignore），
  签名文件也不入库（构建时自动生成，换机器等于换签名，需卸载重装）。
